Web Design (Year 3) សៀវភៅគោល (Core Textbook)
📄 ស្តង់ដាសៀវភៅគោល A4 (Left 2.5cm, Right 1.5cm, Top 2.5cm, Bottom 2.5cm)

សាកលវិទ្យាល័យភូមិន្ទ — មហាវិទ្យាល័យវិទ្យាសាស្ត្រកុំព្យូទ័រ

មុខវិជ្ជា៖ ការរចនាគេហទំព័រ (Web Design — Bachelor Year 3)

ម៉ូឌុល ០១៖ មូលដ្ឋានគ្រឹះនៃការរចនាគេហទំព័រ និង UI/UX (Web Design Fundamentals & UI/UX)

ជំពូកទី ៣៖ មូលដ្ឋានគ្រឹះនៃ UI និង UX (UI and UX Fundamentals)

កម្រិតសិក្សា៖ ថ្នាក់បរិញ្ញាបត្រឆ្នាំទី ៣ | រយៈពេលបង្រៀន៖ ៣ ម៉ោងសិក្សា | ស្តង់ដាឯកសារ៖ Core Textbook

គោលបំណងនៃការរៀនសូត្រ (Learning Objectives)

បន្ទាប់ពីបញ្ចប់ជំពូកទី ៣ នេះ និស្សិតនឹងមានសមត្ថភាពចំណេះដឹង និងបំណិនដូចខាងក្រោម៖

  • ១. ការយល់ដឹងពី UI និង UX៖ ពន្យល់បានច្បាស់លាស់ពីនិយមន័យនៃ User Interface (UI) និង User Experience (UX) ព្រមទាំងភាពខុសគ្នាដាច់ស្រឡះរវាងមុខវិជ្ជាទាំងពីរ។
  • ២. អ្នកប្រើប្រាស់ និងតម្រូវការ៖ វិភាគស្វែងយល់ពីតម្រូវការ (User Needs), គោលដៅ (User Goals) និងផ្នត់គំនិតរបស់អ្នកប្រើប្រាស់ (Mental Models)។
  • ៣. User Journey & User Flow៖ ចេះគូរផែនទីដំណើរកម្សាន្តរបស់អ្នកប្រើប្រាស់ (User Journey Map) និងលំហូរអ្នកប្រើប្រាស់ (User Flow)។
  • ៤. Usability & Accessibility៖ ក្តាប់បាននូវគោលការណ៍គុណភាព Usability ទាំង ៥ របស់ Jakob Nielsen និងស្តង់ដា Accessibility (WCAG 2.1)។
  • ៥. គោលការណ៍ស្នូលទាំង ៤៖ អនុវត្តគោលការណ៍គ្រឹះនៃ UX៖ ភាពស៊ីសង្វាក់គ្នា (Consistency), ភាពសាមញ្ញ (Simplicity & Hick's Law), ការឆ្លើយតប (Feedback) និងការបង្ការកំហុស (Error Prevention)។
  • ៦. ដំណើរការរចនា Design Thinking៖ យល់ដឹង និងចេះអនុវត្តដំណើរការរចនា UI/UX (UI/UX Design Process) តាមទ្រឹស្តី Design Thinking ៥ ដំណាក់កាល។

៣.១ និយមន័យនៃចំណុចប្រទាក់អ្នកប្រើប្រាស់ (Definition of User Interface - UI)

ចំណុចប្រទាក់អ្នកប្រើប្រាស់ (User Interface - UI) គឺជាចំណុចប្រាស្រ័យទាក់ទងដោយផ្ទាល់រវាងមនុស្ស និងប្រព័ន្ធកុំព្យូទ័រ។ នៅក្នុងបរិបទនៃការរចនាគេហទំព័រ UI គឺជាអ្វីៗទាំងអស់ដែលអ្នកប្រើប្រាស់អាចមើលឃើញ ប៉ះពាល់ និងមានអន្តរកម្មជាមួយនៅលើអេក្រង់ (The Visual and Interactive Layer)។ UI រួមបញ្ចូលទាំង៖ ប្លង់ទំព័រ (Layouts), ពណ៌ (Colors), ប្រព័ន្ធពុម្ពអក្សរ (Typography), ប៊ូតុង (Buttons), និមិត្តសញ្ញា (Icons), រូបភាព និងចលនាផ្លាស់ប្តូរ (Animations/Transitions)។ គោលដៅចម្បងរបស់ UI គឺធ្វើឱ្យចំណុចប្រទាក់មើលទៅមានសោភ័ណភាពស្រស់ស្អាត ទាក់ទាញភ្នែក និងមានភាពវិចារណញាណខ្ពស់ (Aesthetically Pleasing & Intuitive)។

៣.២ និយមន័យនៃបទពិសោធអ្នកប្រើប្រាស់ (Definition of User Experience - UX)

បទពិសោធអ្នកប្រើប្រាស់ (User Experience - UX) គឺជាអារម្មណ៍ សតិអារម្មណ៍ និងការយល់ឃើញជារួមរបស់មនុស្សម្នាក់ នៅពេលដែលពួកគេកំពុងមានអន្តរកម្មជាមួយផលិតផល ឬសេវាកម្មគេហទំព័រ (Overall Experience & Perception)។ UX មិនមែនគ្រាន់តែជាអ្វីដែលបង្ហាញនៅលើអេក្រង់ប៉ុណ្ណោះទេ ប៉ុន្តែវាគ្របដណ្តប់លើ៖ ភាពងាយស្រួលក្នុងការស្វែងរកព័ត៌មាន (Findability), ល្បឿនផ្ទុកទំព័រ (Performance), ប្រសិទ្ធភាពក្នុងការបំពេញកិច្ចការ (Efficiency), និងអារម្មណ៍ពេញចិត្តក្រោយពេលប្រើប្រាស់ចប់ (User Satisfaction)។ គោលដៅចម្បងរបស់ UX គឺដោះស្រាយបញ្ហារបស់អ្នកប្រើប្រាស់ដោយរលូន គ្មានឧបសគ្គ (Frictionless) និងមានប្រយោជន៍ពិតប្រាកដ។

៣.៣ ភាពខុសគ្នារវាង UI និង UX (Difference Between UI and UX)

លក្ខណៈប្រៀបធៀប User Interface (UI) User Experience (UX)
ការផ្តោតសំខាន់ (Focus) សោភ័ណភាព និងចំណុចប្រទាក់ក្រាហ្វិក (Visuals, Styling, Components) តក្កវិជ្ជា ការដោះស្រាយបញ្ហា និងអារម្មណ៍ (Logic, Functionality, Journey)
សំណួរគន្លឹះ (Core Question) «តើវាមានរូបរាងដូចម្តេច? (How does it look?)» «តើវាដំណើរការ និងមានអារម្មណ៍យ៉ាងណា? (How does it work & feel?)»
ឧបករណ៍ប្រើប្រាស់ (Tools) Figma, Adobe XD, Illustrator, Color Palettes User Interviews, Journey Maps, User Flows, Wireframes, Usability Testing
ភាពប្រៀបធៀបឡាន ពណ៌រថយន្ត ពូកស្បែក ចង្កូតស្រោបប្រាក់ ផ្ទាំងកុងទ័រ ម៉ាស៊ីនរត់ស្រួល សុវត្ថិភាព ស៊ីសាំងតិច ផាសុកភាពពេលបើកបរ
ភាពប្រៀបធៀបនំខេក ការតែងលម្អក្រែម ផ្លែឈើ និងទៀននៅលើនំ (Icing & Frosting) រសជាតិនំ ភាពទន់ឆ្ងាញ់ និងគុណភាពអាហារូបត្ថម្ភ (Taste & Texture)
⇄ អូសទៅស្តាំដើម្បីមើលតារាងពេញ (Scroll table horizontally)

៣.៤ អ្នកប្រើប្រាស់ (User)

នៅក្នុងការរចនាគេហទំព័រ ពាក្យថា «អ្នកប្រើប្រាស់ (User)» គឺជាបេះដូងនៃគ្រប់ការសម្រេចចិត្តទាំងអស់ (User-Centered Design - UCD)។ ផ្នត់គំនិតរបស់អ្នកប្រើប្រាស់ (Mental Models)៖ គឺជាការយល់ឃើញ និងការរំពឹងទុកទុកជាមុននៅក្នុងខួរក្បាលរបស់អ្នកប្រើប្រាស់ អំពីរបៀបដែលប្រព័ន្ធមួយគួរតែដំណើរការ ដោយផ្អែកលើបទពិសោធពីមុនៗរបស់ពួកគេ។ ឧទាហរណ៍៖ អ្នកប្រើប្រាស់រំពឹងថា រូបសញ្ញាកន្ត្រកទំនិញ (Cart Icon) ត្រូវតែស្ថិតនៅជ្រុងខាងស្តាំលើនៃ Header ហើយការចុចលើ Logo ត្រូវតែនាំត្រឡប់ទៅ Homepage វិញ។

៣.៥ តម្រូវការរបស់អ្នកប្រើប្រាស់ (User Needs)

  • ១. តម្រូវការមុខងារ (Functional Needs): តម្រូវការជាក់ស្តែងដើម្បីបំពេញកិច្ចការណាមួយ ដូចជា៖ ត្រូវការស្វែងរកវគ្គសិក្សា, ត្រូវការបង់ប្រាក់ថ្លៃសិក្សា, ត្រូវការទាញយកកាលវិភាគប្រឡង។
  • ២. តម្រូវការផ្លូវចិត្ត (Emotional Needs): អារម្មណ៍ដែលអ្នកប្រើប្រាស់ចង់ទទួលបានក្នុងពេលប្រើប្រាស់ ដូចជា៖ អារម្មណ៍សុវត្ថិភាពពេលបញ្ចូលលេខកាត, អារម្មណ៍ជឿជាក់លើកិត្យានុភាពសាកលវិទ្យាល័យ។

៣.៦ គោលដៅរបស់អ្នកប្រើប្រាស់ (User Goals)

  • គោលដៅចុងក្រោយ (End Goals): អ្វីដែលអ្នកប្រើប្រាស់ចង់សម្រេចបានក្នុងកិច្ចការជាក់ស្តែង (ឧទាហរណ៍៖ ទិញកុំព្យូទ័រមួយគ្រឿងឱ្យបានជោគជ័យ)។
  • គោលដៅបទពិសោធន៍ (Experience Goals): អារម្មណ៍ដែលពួកគេចង់ទទួលបានក្នុងដំណើរការប្រើប្រាស់ (ឧទាហរណ៍៖ មិនចង់មានអារម្មណ៍ល្ងង់ ឬធុញថប់ក្នុងការបំពេញ Form វែងៗ)។
  • គោលដៅជីវិត (Life Goals): សេចក្តីប្រាថ្នារយៈពេលវែងក្នុងជីវិត (ឧទាហរណ៍៖ ក្លាយជាវិស្វករសូហ្វវែរឆ្នើម)។

៣.៧ ដំណើររបស់អ្នកប្រើប្រាស់ (User Journey)

ដំណើររបស់អ្នកប្រើប្រាស់ (User Journey) រួមមាន ៥ ជំហាន៖

  • ១. ការយល់ដឹង (Awareness): អ្នកប្រើប្រាស់ដឹងពីបញ្ហារបស់ខ្លួន និងចាប់ផ្តើមស្វែងរកដំណោះស្រាយ។
  • ២. ការពិចារណា (Consideration): ចូលមកទស្សនាគេហទំព័រ ប្រៀបធៀបតម្លៃ និងពិនិត្យលក្ខណៈសម្បត្តិផលិតផល។
  • ៣. ការទិញ ឬចុះឈ្មោះ (Purchase / Conversion): សម្រេចចិត្តចុះឈ្មោះ ឬទិញទំនិញតាមរយៈ Checkout Flow។
  • ៤. ការរក្សាអតិថិជន (Retention): ទទួលបានសេវាកម្មគាំទ្រល្អ និងបន្តប្រើប្រាស់គេហទំព័រជាប្រចាំ។
  • ៥. ការគាំទ្រ និងផ្សព្វផ្សាយ (Advocacy): ពេញចិត្តយ៉ាងខ្លាំង និងណែនាំគេហទំព័រនេះទៅកាន់មិត្តភក្តិបន្ត។

៣.៨ លំហូររបស់អ្នកប្រើប្រាស់ (User Flow)

លំហូររបស់អ្នកប្រើប្រាស់ (User Flow) គឺជាគំនូសបំព្រួញមួយជំហានម្តងៗ (Step-by-step Flowchart) ដែលបង្ហាញពីផ្លូវដែលអ្នកប្រើប្រាស់ត្រូវដើរពីចំណុចចាប់ផ្តើម (Entry Point) រហូតដល់សម្រេចគោលដៅជាក់លាក់ណាមួយ (Success State) នៅក្នុងគេហទំព័រ។

៣.៩ ភាពងាយស្រួលប្រើប្រាស់ (Usability)

សូចនាករគុណភាពទាំង ៥ របស់ Jakob Nielsen៖

  • ១. ភាពងាយរៀន (Learnability): អ្នកប្រើប្រាស់លើកដំបូងអាចរៀនប្រើប្រព័ន្ធបានលឿន។
  • ២. ប្រសិទ្ធភាពការងារ (Efficiency): អាចបំពេញការងារបានលឿនពេលស្ទាត់ជំនាញ។
  • ៣. ភាពងាយចងចាំ (Memorability): ងាយចាំវិធីប្រើទោះបីខកខានប្រើមួយរយៈ។
  • ៤. អត្រាកំហុសទាប (Errors): កំហុសកើតឡើងតិច និងអាចកែប្រែវិញបានលឿន។
  • ៥. ភាពពេញចិត្ត (Satisfaction): អ្នកប្រើប្រាស់មានអារម្មណ៍រីករាយ និងពេញចិត្តក្នុងការប្រើប្រាស់។

៣.១០ លទ្ធភាពទទួលបាន (Accessibility - a11y)

គោលការណ៍គ្រឹះទាំង ៤ នៃ WCAG 2.1 គឺ POUR៖

  • Perceivable (អាចដឹងបាន): ព័ត៌មានត្រូវតែបង្ហាញក្នុងទម្រង់ដែលញ្ញាណរបស់មនុស្សអាចចាប់បាន (ឧ. alt text សម្រាប់រូបភាព)។
  • Operable (អាចដំណើរការបាន): អាចបញ្ជាបានតាមក្តារចុច (Keyboard Navigable)។
  • Understandable (អាចយល់បាន): អត្ថបទ និងទម្រង់បែបបទងាយយល់ មានការណែនាំច្បាស់។
  • Robust (រឹងមាំ): កូដអនុលោមតាមស្តង់ដា W3C ដំណើរការបានលើគ្រប់ Browser និង Assistive Tech។

៣.១១ ភាពស៊ីសង្វាក់គ្នា (Consistency)

រួមមាន Visual Consistency (ពណ៌ ពុម្ពអក្សរ ប៊ូតុងដូចៗគ្នា), Functional Consistency (ធាតុដូចគ្នាដំណើរការដូចគ្នា), និង External Consistency (គោរពស្តង់ដាទូទៅលើវេប)។

៣.១២ ភាពសាមញ្ញ (Simplicity)

ច្បាប់របស់ Hick (Hick's Law)៖ «ពេលវេលាដែលមនុស្សម្នាក់ត្រូវការដើម្បីធ្វើការសម្រេចចិត្ត នឹងកើនឡើងទៅតាមចំនួន និងភាពស្មុគស្មាញនៃជម្រើសដែលមាន»។ ត្រូវបំបែកកិច្ចការស្មុគស្មាញឱ្យទៅជាជំហានខ្លីៗ (Stepped Flow)។

៣.១៣ ការឆ្លើយតបព័ត៌មាន (Feedback)

Visibility of System Status តាមរយៈ៖ Loading Spinners, Toast Notifications, និង Button Hover/Active Micro-interactions។

៣.១៤ ការបង្ការកំហុស (Error Prevention)

  • Inline Real-Time Validation: បង្ហាញកំហុសភ្លាមៗនៅពេលវាយខុស។
  • Constraints: ប្រើ Dropdown ឬ Date Picker ជំនួសឱ្យការវាយដោយដៃ។
  • Confirmation Safeguards: បង្ហាញ Modal សួរមុនពេលលុបទិន្នន័យ។

៣.១៥ ដំណើរការរចនា UI/UX (UI/UX Design Process)

ទ្រឹស្តី Design Thinking ៥ ដំណាក់កាល៖

  1. Empathize: យល់ចិត្ត និងអង្កេតបញ្ហារបស់អ្នកប្រើប្រាស់ពិត។
  2. Define: កំណត់សេចក្តីថ្លែងការណ៍បញ្ហាស្នូល (Problem Statement)។
  3. Ideate: បំផុសគំនិតរកដំណោះស្រាយជាច្រើន (Brainstorming)។
  4. Prototype: បង្កើតគំរូសាកល្បងពី Wireframe ទៅ Clickable Prototype។
  5. Test: ធ្វើតេស្ត Usability Testing ជាមួយអ្នកប្រើប្រាស់ពិត។

សេចក្តីសង្ខេបមេរៀន (Chapter Summary)

ជំពូកទី ៣ បានផ្តល់នូវមូលដ្ឋានគ្រឹះយ៉ាងជ្រាលជ្រៅអំពីការយល់ដឹងពីមនុស្ស (User) នៅក្នុងវិស្វកម្មគេហទំព័រ។ UI ផ្តល់នូវរូបរាង និងសោភ័ណភាព ខណៈដែល UX ធានានូវភាពរលូន និងប្រសិទ្ធភាពក្នុងការដោះស្រាយបញ្ហា។ គេហទំព័រដែលជោគជ័យត្រូវតែប្រកាន់ខ្ជាប់នូវគោលការណ៍ Usability, Accessibility (WCAG POUR), ភាពស៊ីសង្វាក់គ្នា (Consistency), ភាពសាមញ្ញតាមច្បាប់ Hick's Law, ការឆ្លើយតបព័ត៌មានរហ័ស (Feedback), និងការបង្ការកំហុស (Error Prevention)។

សំណួរត្រួតពិនិត្យការយល់ដឹង (Review & Discussion Questions)

  1. ចូរពន្យល់ពីភាពខុសគ្នារវាង UI និង UX ដោយលើកយកការប្រៀបធៀបជាក់ស្តែងមួយមកពន្យល់ (ឧទាហរណ៍៖ រថយន្ត ឬនំខេក)។
  2. តើអ្វីទៅជា «Mental Model» របស់អ្នកប្រើប្រាស់? ហេតុអ្វីបានជាអ្នករចនាមិនគួររចនាបំពាន Mental Model? លើកឧទាហរណ៍មួយមកបញ្ជាក់។
  3. ចូររៀបរាប់ពីគោលការណ៍គ្រឹះទាំង ៤ នៃស្តង់ដា Web Accessibility (WCAG 2.1 POUR)។
  4. តើច្បាប់របស់ Hick (Hick's Law) ជះឥទ្ធិពលយ៉ាងដូចម្តេចខ្លះទៅលើការរចនាប្រព័ន្ធ Checkout នៃគេហទំព័រ E-Commerce?
  5. ចូររៀបរាប់ពីដំណាក់កាលទាំង ៥ នៃដំណើរការ Design Thinking ក្នុងការរចនា UI/UX (Empathize, Define, Ideate, Prototype, Test)។
