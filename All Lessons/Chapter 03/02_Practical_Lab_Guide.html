សាកលវិទ្យាល័យភូមិន្ទ — មហាវិទ្យាល័យវិទ្យាសាស្ត្រកុំព្យូទ័រ

កិច្ចការអនុវត្តជាក់ស្តែងក្នុងបន្ទប់ពិសោធន៍ (Practical Lab Guide)

ម៉ូឌុល ០១ • ជំពូកទី ៣៖ ការបង្កើតលំហូរអ្នកប្រើប្រាស់សម្រាប់គេហទំព័រ E-Commerce (Create a User Flow for an E-Commerce Website)

កម្រិតសិក្សា៖ បរិញ្ញាបត្រឆ្នាំទី ៣ | រយៈពេលអនុវត្ត៖ ៣ ម៉ោង | ប្រភេទទម្រង់៖ Step-by-Step Practical Lab

គោលបំណងនៃការអនុវត្ត (Lab Objectives)

  • ១. ស្វែងយល់ User Flow៖ យល់ច្បាស់ពីតួនាទីរបស់ User Flow ក្នុងការរចនាបទពិសោធអ្នកប្រើប្រាស់លើគេហទំព័រពាណិជ្ជកម្មអេឡិចត្រូនិក។
  • ២. Happy Path vs Edge Cases៖ កំណត់ផ្លូវជោគជ័យ (Happy Path) និងផ្លូវជំនួស/កំហុស (Alternate & Error Paths) ក្នុង Checkout Flow។
  • ៣. គំនូសបំព្រួញ Diagram៖ ប្រើប្រាស់ឧបករណ៍ឌីជីថល (FigJam / Miro / draw.io) ដើម្បីគូរគំនូសបំព្រួញ User Flow Diagram តាមស្តង់ដាអន្តរជាតិ។
  • ៤. ការបង្ការកំហុស និង Feedback៖ អនុវត្តគោលការណ៍ Error Prevention, Inline Validation, និង Feedback ក្នុងគ្រប់ជំហាននៃលំហូរ។
  • ៥. របាយការណ៍បច្ចេកទេស៖ ចងក្រងជារបាយការណ៍បច្ចេកទេស និងការពារគម្រោងអនុវត្តរបស់ខ្លួន។

ការណែនាំអនុវត្តជាជំហានៗ (Step-by-Step Lab Instructions)

ជំហានទី ១៖ កំណត់ User Persona និងគោលបំណងទិញទំនិញ

  • Persona Profile: ឈ្មោះ៖ សុខ សុវណ្ណ | អាយុ៖ ២១ ឆ្នាំ | មុខរបរ៖ និស្សិតឆ្នាំទី ៣ ផ្នែក IT។
  • User Goal: ត្រូវការទិញកុំព្យូទ័រ Laptop ថ្មីសម្រាប់រៀនសរសេរកូដ ដោយប្រើ Voucher បញ្ចុះតម្លៃនិស្សិត និងទូទាត់ប្រាក់តាម Bakong KHQR។

ជំហានទី ២៖ វិភាគកិច្ចការ (Task Analysis) និងកំណត់លំដាប់លំហូរ

  1. Product Details: ជ្រើសរើសពណ៌ ទំហំ Storage និងចុច Add to Cart។
  2. Cart Review: ពិនិត្យតម្លៃ បញ្ចូលកូដ Voucher និងពិនិត្យតម្លៃសរុប។
  3. Shipping Details: បំពេញអាសយដ្ឋានដឹកជញ្ជូនជាមួយ Inline Real-time Validation។
  4. Payment Method: ជ្រើសរើសវិធីសាស្ត្រ Bakong KHQR និងស្កេនទូទាត់។
  5. Order Success: ទទួលបានវិក្កយបត្រអេឡិចត្រូនិក និងលេខកូដ Order ID។

ជំហានទី ៣៖ ការគូសប្លង់ User Flow Diagram តាមស្តង់ដា

[Start: ចូលទស្សនា] → [Action: ជ្រើសរើស Options] → [Action: Add to Cart] → <Decision: មាន Voucher?> → [Action: បំពេញអាសយដ្ឋាន] → <Decision: ត្រឹមត្រូវ?> → [Action: ស្កេន Bakong KHQR] → [End: វិក្កយបត្រជោគជ័យ]

ជំហានទី ៤៖ អនុវត្ត និងត្រួតពិនិត្យគោលការណ៍ UI/UX ក្នុងគម្រោងគំរូ

បើកឯកសារ sample_project/index.html រួចធ្វើតេស្ត៖

  • ១. Error Prevention Test: សាកល្បងចុច «សម្អាតកន្ត្រក» ដើម្បីសង្កេតមើលផ្ទាំង Confirmation Alert។
  • ២. Form Validation Test: វាយបញ្ចូលទិន្នន័យខុសទម្រង់ ដើម្បីសង្កេតមើល Inline Real-time Error Message។
  • ៣. Feedback Test: បញ្ចូលកូដ 'STUDENT2026' ដើម្បីមើលការគណនាតម្លៃ និង Toast Feedback ពណ៌បៃតង។

ទម្រង់របាយការណ៍បច្ចេកទេសរបស់និស្សិត (Student Submission Template)

ដំណាក់កាលលំហូរ (Flow Step) សកម្មភាពអ្នកប្រើ (User Action) ការឆ្លើយតបប្រព័ន្ធ (System Feedback) ការបង្ការកំហុស (Error Prevention)
Step 1: Product Config ជ្រើសរើសពណ៌ និងទំហំ Storage ផ្លាស់ប្តូររូបភាព និងតម្លៃភ្លាមៗ កម្រិតបរិមាណអតិបរមា ៥ គ្រឿង
Step 2: Cart Review បញ្ចូលលេខកូដ 'STUDENT2026' បង្ហាញ Toast បញ្ចុះតម្លៃ ១០% ភ្លាមៗ សួរ Confirmation មុនសម្អាតកន្ត្រក
Step 3: Shipping Form វាយបញ្ចូលឈ្មោះ លេខទូរស័ព្ទ អ៊ីមែល បង្ហាញ Inline Error ក្រហមពេលវាយខុស មិនអនុញ្ញាតឱ្យបន្តបើទម្រង់មិនត្រឹមត្រូវ
Step 4: Payment ស្កេនទូទាត់ Bakong KHQR បង្ហាញ Countdown Timer ០៥:០០ នាទី ទប់ស្កាត់ការចុច Submit ផ្ទួនៗ (Disabled)
⇄ អូសទៅស្តាំដើម្បីមើលតារាងពេញ (Scroll table horizontally)

តារាងពិន្ទុវាយតម្លៃការអនុវត្ត (Evaluation Rubric — 100 Points)

  • ១. ការវិភាគតម្រូវការ និង Persona (២៥ ពិន្ទុ)៖ កំណត់ User Persona និងវិភាគ Task Analysis បានត្រឹមត្រូវពេញលេញ។
  • ២. គុណភាពនៃ User Flow Diagram (២៥ ពិន្ទុ)៖ គូសប្លង់ User Flow Diagram ៥ ដំណាក់កាលច្បាស់លាស់ ត្រឹមត្រូវតាមស្តង់ដានិមិត្តសញ្ញា។
  • ៣. ការរចនា Feedback & Micro-interactions (២៥ ពិន្ទុ)៖ បង្កប់នូវយន្តការ Feedback, Toast Notifications, និង Loading State បានត្រឹមត្រូវ។
  • ៤. យុទ្ធសាស្ត្រ Error Prevention (២៥ ពិន្ទុ)៖ មានយន្តការបង្ការកំហុស Inline Real-time Form Validation និង Confirmation Safeguards។
