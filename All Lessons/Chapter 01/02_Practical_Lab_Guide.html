Web Design (Year 3) មន្ទីរពិសោធន៍អនុវត្ត (Practical Lab Guide)
📄 ស្តង់ដាសៀវភៅគោល A4 (Left 2.5cm, Right 1.5cm, Top 2.5cm, Bottom 2.5cm)

សាកលវិទ្យាល័យភូមិន្ទ — មហាវិទ្យាល័យវិទ្យាសាស្ត្រកុំព្យូទ័រ

កិច្ចការអនុវត្តជាក់ស្តែងក្នុងបន្ទប់ពិសោធន៍ (Practical Lab Guide)

ម៉ូឌុល ០១ • ជំពូកទី ១៖ ការវិភាគគេហទំព័រអាជីពចំនួន ៣ (Analyze Three Professional Websites)

កម្រិតសិក្សា៖ បរិញ្ញាបត្រឆ្នាំទី ៣ | រយៈពេលអនុវត្ត៖ ៣ ម៉ោង | ប្រភេទទម្រង់៖ Step-by-Step Practical Lab

គោលបំណងនៃការអនុវត្ត (Lab Objectives)

  • ១. ជំនាញ DevTools៖ ប្រើប្រាស់ Browser Developer Tools (F12) លើ Google Chrome ឬ Microsoft Edge ក្នុងការត្រួតពិនិត្យកូដប្រភពគេហទំព័រផ្ទាល់។
  • ២. ការវិភាគរចនាសម្ព័ន្ធ៖ ស្វែងយល់ជាក់ស្តែងពីរបៀបដែលគេហទំព័រអាជីពរៀបចំ Semantic HTML, CSS Stylesheet, និង JavaScript Assets។
  • ៣. ការវាស់វែង Network៖ វាស់វែងល្បឿនផ្ទុកទំព័រ (Load Time), ចំនួន HTTP Requests, ទំហំទិន្នន័យ (Transferred Size) និង Status Codes លើ Network Panel។
  • ៤. ការធ្វើតេស្ត Responsive៖ វាយតម្លៃសមត្ថភាពសម្របតាមទំហំអេក្រង់ (Responsive Design) លើទូរស័ព្ទ Tablet និងកុំព្យូទ័រលើតុ។
  • ៥. របាយការណ៍បច្ចេកទេស៖ ចងក្រងជារបាយការណ៍បច្ចេកទេស និងតារាងប្រៀបធៀបតាមស្តង់ដាវិស្វកម្មគេហទំព័រ។

សម្ភារ និងបរិស្ថានអនុវត្តដែលត្រូវការ (Required Tools & Setup)

  • Hardware: កុំព្យូទ័រដែលមានប្រព័ន្ធប្រតិបត្តិការ Windows / macOS / Linux និងភ្ជាប់អ៊ីនធឺណិត។
  • Web Browser: Google Chrome (កំណែ 110+) ឬ Microsoft Edge (កំណែ Chromium-based)។
  • Code Editor: Visual Studio Code (សម្រាប់កត់ត្រា និងបើកកូដគំរូ)។
  • Sample Project: គម្រោងគំរូ «sample_project» ដែលមាននៅក្នុង Folder មេរៀន។

ការណែនាំអនុវត្តជាជំហានៗ (Step-by-Step Lab Instructions)

ជំហានទី ១៖ កម្តៅសាច់ដុំជាមួយ Browser DevTools (DevTools Warm-Up)

១. បើក Browser Google Chrome ឬ Microsoft Edge រួចបើកឯកសារ sample_project/index.html នៅក្នុងម៉ាស៊ីនរបស់អ្នក។

២. ចុចគ្រាប់ចុច F12 ឬបន្សំគ្រាប់ចុច Ctrl + Shift + I នៅលើក្តារចុច (Keyboard)។

៣. ការអនុវត្តលើផ្ទាំង Elements៖

  • ក. ត្រួតពិនិត្យ Element: ចុចលើរូបសញ្ញាព្រួញជ្រើសរើស (Inspect element icon នៅជ្រុងខាងឆ្វេងលើបំផុតនៃ DevTools) រួចយកទៅចុចលើចំណងជើង «Web Tech Explorer» ក្នុងទំព័រ។
  • ខ. កែប្រែអត្ថបទផ្ទាល់ (Live Text Editing): នៅលើផ្ទាំង Elements ចុចកណ្ដុរពីរដងលើអត្ថបទចំណងជើង រួចប្តូរទៅជាឈ្មោះផ្ទាល់ខ្លួនរបស់អ្នក។ សង្កេតមើលការផ្លាស់ប្តូរភ្លាមៗលើអេក្រង់។
  • គ. កែប្រែពណ៌ CSS ផ្ទាល់ (Live CSS Editing): នៅផ្ទាំង Styles (ខាងស្តាំ) រកមើល property color រួចចុចប្តូរពណ៌។ សង្កេតមើលថាតើហេតុអ្វីបានជាការកែប្រែនេះបាត់ទៅវិញនៅពេលយើង Refresh ទំព័រ (F5)។

៤. ការអនុវត្តលើផ្ទាំង Console៖

  • ក. បញ្ជាកូដ: ចូលទៅកាន់ផ្ទាំង Console រួចវាយបញ្ចូល៖ console.log("Hello Web Design Year 3!"); រួចចុច Enter។
  • ខ. ប្តូរចំណងជើង Tab: វាយបញ្ចូល៖ document.title = "My Custom Title"; រួចពិនិត្យមើលចំណងជើងនៅលើ Tab នៃ Browser របស់អ្នក។

៥. ការអនុវត្តលើ Responsive Device Toolbar៖

  • ក. បើក Device Mode: ចុចលើរូបសញ្ញាទូរស័ព្ទ/Tablet (Toggle device toolbar - Ctrl + Shift + M)។
  • ខ. ពិនិត្យការសម្របខ្លួន: ជ្រើសរើសទំហំឧបករណ៍ «iPhone 14 Pro» និង «iPad Air» រួចសង្កេតមើលប្លង់ Layout ថាតើវាសម្របខ្លួនយ៉ាងដូចម្តេច។

ជំហានទី ២៖ ជ្រើសរើស និងវិភាគគេហទំព័រអាជីពចំនួន ៣ (Site Selection & Audit)

និស្សិតម្នាក់ៗត្រូវជ្រើសរើសគេហទំព័រអាជីពចំនួន ៣ ដែលមានប្រភេទខុសគ្នាដាច់ស្រឡះ ដើម្បីធ្វើការវិភាគ៖

  • គេហទំព័រទី ១ (Static / Portfolio Website): ជ្រើសរើសគេហទំព័ររបស់ Developer ឬ Designer អាជីពម្នាក់ (ឧទាហរណ៍៖ leerob.io, bruno-simon.com, ឬ portfolio ផ្ទាល់ខ្លួន)។
  • គេហទំព័រទី ២ (Corporate / Dynamic Media Portal): ជ្រើសរើសគេហទំព័រស្ថាប័នធំ ឬសារព័ត៌មានអន្តរជាតិ (ឧទាហរណ៍៖ apple.com, bbc.com, ឬ wikipedia.org)។
  • គេហទំព័រទី ៣ (E-Commerce / Complex Web App): ជ្រើសរើសគេហទំព័រពាណិជ្ជកម្មអេឡិចត្រូនិក ឬ Web App (ឧទាហរណ៍៖ amazon.com, canva.com, ឬ figma.com)។

ជំហានទី ៣៖ ការប្រមូលទិន្នន័យបច្ចេកទេសជាក់ស្តែងតាម Network Panel

សម្រាប់គេហទំព័រនីមួយៗក្នុងចំណោមទាំង ៣ សូមអនុវត្តតាមលំដាប់លំដោយដូចខាងក្រោម៖

  • ១. របៀបស្អាត: បើកគេហទំព័រនោះក្នុង Incognito Window (ដើម្បីកុំឱ្យជាប់ Cache ឬ Extension នានា)។
  • ២. បិទ Cache: បើក DevTools រួចចុចចូលផ្ទាំង Network។ គូសធីកលើប្រអប់ «Disable cache»។
  • ៣. ទាញយកឡើងវិញ: ចុចគ្រាប់ចុច Ctrl + F5 (Hard Reload) ដើម្បីទាញយកទិន្នន័យថ្មីទាំងអស់ពី Server។
  • ៤. កត់ត្រាទិន្នន័យ: សង្កេតមើលរបាយការណ៍សង្ខេបនៅរបារខាងក្រោមនៃ Network Panel រួចកត់ត្រា៖ ចំនួន Requests សរុប, ទំហំ Transferred (ទិន្នន័យបង្ហាប់), ទំហំ Resources (ទិន្នន័យពិត), និងរយៈពេល Finish / Load Time។
  • ៥. វិភាគធនធាន: ត្រួតពិនិត្យប្រភេទធនធាន (Filter by Doc, CSS, JS, Img) ដើម្បីដឹងថាតើទំហំធ្ងន់បំផុតបណ្តាលមកពីអ្វី (រូបភាព ឬ JavaScript)។

ជំហានទី ៤៖ ការវាយតម្លៃគុណភាពតាមរយៈ Lighthouse Audit

១. នៅលើ DevTools ចូលទៅកាន់ផ្ទាំង «Lighthouse»។

២. ជ្រើសរើស Mode: Navigation | Device: Mobile (ឬ Desktop) | Categories: គូសធីកទាំងអស់ (Performance, Accessibility, Best Practices, SEO)។

៣. ចុចប៊ូតុង «Analyze page load» រួចរង់ចាំប្រព័ន្ធដំណើរការប្រហែល ៣០ ទៅ ៦០ វិនាទី។

៤. កត់ត្រាពិន្ទុទាំង ៤ និងចំណុចខ្វះខាតធំៗដែល Lighthouse បានផ្តល់អនុសាសន៍។

តារាងពិន្ទុវាយតម្លៃការអនុវត្ត (Evaluation Rubric — 100 Points)

  • ១. ភាពត្រឹមត្រូវនៃទិន្នន័យ DevTools (២៥ ពិន្ទុ)៖ ជ្រើសរើសគេហទំព័រត្រូវតាម ៣ ប្រភេទខុសគ្នា និងប្រមូលទិន្នន័យ Requests, Size, Load Time បានត្រឹមត្រូវពេញលេញ។
  • ២. ការវិភាគរចនាសម្ព័ន្ធកូដ (២៥ ពិន្ទុ)៖ យល់ដឹងច្បាស់ពីតួនាទីរបស់ DOM Elements, CSS Stylesheet, និង Console Errors លើគេហទំព័រនីមួយៗ។
  • ៣. ការវាយតម្លៃ Lighthouse & Responsive (២៥ ពិន្ទុ)៖ ដំណើរការ Lighthouse និងពន្យល់ពីមូលហេតុដែលនាំឱ្យពិន្ទុ Performance ឬ Accessibility ខ្ពស់ ឬទាប។
  • ៤. សេចក្តីសន្និដ្ឋាន និងការរៀបចំរបាយការណ៍ (២៥ ពិន្ទុ)៖ សរសេរអធិប្បាយ និងទាញសេចក្តីសន្និដ្ឋានប្រៀបធៀបរវាងគេហទំព័រទាំង ៣ ប្រកបដោយភាពចាស់ទុំ និងវិជ្ជាជីវៈ។
