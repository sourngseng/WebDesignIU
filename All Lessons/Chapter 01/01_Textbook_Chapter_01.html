សាកលវិទ្យាល័យភូមិន្ទ — មហាវិទ្យាល័យវិទ្យាសាស្ត្រកុំព្យូទ័រ

មុខវិជ្ជា៖ ការរចនាគេហទំព័រ (Web Design — Bachelor Year 3)

ម៉ូឌុល ០១៖ មូលដ្ឋានគ្រឹះនៃការរចនាគេហទំព័រ និង UI/UX (Web Design Fundamentals & UI/UX)

ជំពូកទី ១៖ សេចក្តីផ្តើមអំពីការរចនាគេហទំព័រ (Introduction to Web Design)

កម្រិតសិក្សា៖ ថ្នាក់បរិញ្ញាបត្រឆ្នាំទី ៣ | រយៈពេលបង្រៀន៖ ៣ ម៉ោងសិក្សា (1.5 Session) | ស្តង់ដាឯកសារ៖ Core Textbook

គោលបំណងនៃការរៀនសូត្រ (Learning Objectives)

បន្ទាប់ពីបញ្ចប់ជំពូកនេះ និស្សិតនឹងមានសមត្ថភាពចំណេះដឹង និងបំណិនដូចខាងក្រោម៖

  • ១. និយមន័យ និងវិសាលភាព៖ អាចពន្យល់ពីនិយមន័យ វិសាលភាព និងគោលដៅនៃការរចនាគេហទំព័រក្នុងបរិបទឧស្សាហកម្មឌីជីថលទំនើប។
  • ២. ប្រវត្តិនៃបណ្តាញវេប៖ យល់ដឹងពីការវិវឌ្ឍជាប្រវត្តិសាស្ត្រពី Web 1.0 (Static), Web 2.0 (Interactive) រហូតដល់ Web 3.0 (Semantic & Decentralized)។
  • ៣. Website ទល់នឹង Web Application៖ ចេះបែងចែកភាពខុសគ្នាដាច់ស្រឡះរវាង Website និង Web Application តាមរយៈលក្ខណៈបច្ចេកទេស និងបទពិសោធអ្នកប្រើប្រាស់។
  • ៤. តួនាទី និងស្ថាបត្យកម្ម៖ យល់ច្បាស់ពីតួនាទី និងទំនួលខុសត្រូវរវាង Web Designer និង Web Developer ព្រមទាំងស្ថាបត្យកម្ម Frontend និង Backend។
  • ៥. សសរស្តម្ភបច្ចេកវិទ្យាទាំងបី៖ វិភាគបានពីតួនាទីស្នូលទាំងបី៖ HTML (គ្រោងឆ្អឹង), CSS (សោភ័ណភាព) និង JavaScript (អន្តរកម្ម) ក្នុងការបង្កើតទំព័រគេហទំព័រ។
  • ៦. យន្តការដំណើរការវេប៖ ពន្យល់បានច្បាស់លាស់ពីយន្តការដំណើរការរបស់ Web Browser, Web Server, DNS Lookup, HTTP/HTTPS Request-Response និង Critical Rendering Path (CRP)។
  • ៧. ប្រភេទគេហទំព័រ៖ កំណត់អត្តសញ្ញាណ និងប្រៀបធៀបប្រភេទគេហទំព័រទាំង ៦ (Static, Dynamic, E-Commerce, Portfolio, Corporate, Educational)។
  • ៨. លំហូរការងារ និងឧបករណ៍៖ យល់ដឹងពីលំហូរការងាររចនាគេហទំព័រអាជីព (Workflow) និងឧបករណ៍ដែលប្រើប្រាស់ក្នុងឧស្សាហកម្ម។
  • ៩. ឧបករណ៍អ្នកអភិវឌ្ឍន៍ (DevTools)៖ ចេះប្រើប្រាស់ឧបករណ៍ Browser Developer Tools (DevTools) ដើម្បីត្រួតពិនិត្យ DOM, Style, Console និង Network Requests។

១.១ និយមន័យនៃការរចនាគេហទំព័រ (Definition of Web Design)

ការរចនាគេហទំព័រ (Web Design) គឺជាសិល្បៈ និងវិទ្យាសាស្ត្រនៃការរៀបចំ គំនិតច្នៃប្រឌិត និងការបង្កើតគេហទំព័រនៅលើបណ្ដាញអ៊ីនធឺណិត។ វាមិនត្រឹមតែជាការជ្រើសរើសរូបភាព ពណ៌ និងពុម្ពអក្សរប៉ុណ្ណោះទេ ប៉ុន្តែគឺជាដំណើរការរួមបញ្ចូលគ្នាយ៉ាងស្មុគស្មាញរវាង សោភ័ណភាពនៃការមើលឃើញ (Visual Design), ស្ថាបត្យកម្មព័ត៌មាន (Information Architecture), បទពិសោធអ្នកប្រើប្រាស់ (User Experience - UX), ចំណុចប្រទាក់អ្នកប្រើប្រាស់ (User Interface - UI) និងការគិតគូរលើលទ្ធភាពបច្ចេកវិទ្យា (Technical Feasibility)។

នៅក្នុងបរិបទនៃការអភិវឌ្ឍន៍សហសម័យ ការរចនាគេហទំព័រត្រូវផ្តោតលើគោលការណ៍គ្រឹះចំនួន ៤ យ៉ាង៖

  • ភាពងាយស្រួលប្រើប្រាស់ (Usability): គេហទំព័រត្រូវតែមានភាពវិចារណញាណ ងាយស្រួលរុករក (Intuitive Navigation) និងអនុញ្ញាតឱ្យអ្នកប្រើប្រាស់សម្រេចគោលបំណងរបស់ពួកគេដោយរលូនបំផុត។
  • លទ្ធភាពទទួលបាន (Accessibility): គេហទំព័រត្រូវរចនាឡើងដើម្បីឱ្យមនុស្សគ្រប់រូប រួមទាំងជនមានពិការភាព (Disabilities) អាចចូលប្រើប្រាស់ និងយល់ខ្លឹមសារបានស្របតាមស្តង់ដា WCAG (Web Content Accessibility Guidelines)។
  • សោភ័ណភាព និងទំនុកចិត្ត (Aesthetic & Credibility): ការប្រើប្រាស់ទ្រឹស្តីពណ៌ ពុម្ពអក្សរ និងចន្លោះទំនេរ (White Space) ឱ្យមានតុល្យភាព ដើម្បីកសាងអត្តសញ្ញាណម៉ាកយីហោ (Brand Identity) គួរឱ្យទុកចិត្ត។
  • ការឆ្លើយតបគ្រប់អេក្រង់ (Responsive Adaptability): គេហទំព័រត្រូវតែរចនាឱ្យសម្របតាមទំហំអេក្រង់គ្រប់ប្រភេទ ចាប់ពីទូរស័ព្ទដៃ Tablet រហូតដល់កុំព្យូទ័រលើតុ (Desktop)។

ភាពខុសគ្នារវាងការរចនាលើក្រដាសបោះពុម្ព (Print Design) និងការរចនាគេហទំព័រ (Web Design)៖

  • ការរចនាលើក្រដាស (Print Design): ផ្ទាំងក្រដាសមានទំហំថេរច្បាស់លាស់ (Fixed Canvas) ដូចជា A4 ឬ Letter, ពណ៌ប្រើប្រព័ន្ធ CMYK, គ្មានអន្តរកម្ម (Static), និងមិនអាចផ្លាស់ប្តូរបានឡើយក្រោយពេលបោះពុម្ព។
  • ការរចនាគេហទំព័រ (Web Design): ផ្ទៃបង្ហាញមានលក្ខណៈបត់បែនគ្មានដែនកំណត់ (Fluid / Dynamic Canvas), ពណ៌ប្រើប្រព័ន្ធឌីជីថល sRGB, មានអន្តរកម្មខ្ពស់ (Interactive), និងអាចកែប្រែធ្វើបច្ចុប្បន្នភាពខ្លឹមសារបានគ្រប់វិនាទី។

១.២ ប្រវត្តិ និងការវិវឌ្ឍនៃបណ្ដាញវេប (History and Evolution of the Web)

បណ្ដាញ World Wide Web (WWW) ត្រូវបានបង្កើតឡើងនៅឆ្នាំ ១៩៨៩ ដោយអ្នកវិទ្យាសាស្ត្រកុំព្យូទ័រជនជាតិអង់គ្លេសឈ្មោះ Sir Tim Berners-Lee នៅមជ្ឈមណ្ឌលស្រាវជ្រាវនុយក្លេអ៊ែរអឺរ៉ុប (CERN) ក្នុងគោលបំណងចែករំលែកឯកសារស្រាវជ្រាវដោយស្វ័យប្រវត្តិតាមរយៈប្រព័ន្ធ Hypertext។ ចាប់តាំងពីពេលនោះមក បណ្តាញវេបបានឆ្លងកាត់ការវិវឌ្ឍយ៉ាងលឿនជា ៣ យុគសម័យធំៗ៖

១. យុគសម័យ Web 1.0 (The Read-Only Web: 1991 – 2004)៖ នៅក្នុងដំណាក់កាលដំបូង គេហទំព័រគឺជាឯកសារឋិតិវន្ត (Static HTML pages) ដែលម្ចាស់គេហទំព័រជាអ្នកសរសេរព័ត៌មាន ហើយអ្នកប្រើប្រាស់គ្រាន់តែជាអ្នកអានទិន្នន័យតែប៉ុណ្ណោះ (One-way communication)។ គេហទំព័រគ្មានប្រព័ន្ធស្វែងរកទិន្នន័យស្មុគស្មាញ គ្មានការចូលប្រើប្រាស់គណនី (Authentication) និងគ្មានការបញ្ចេញមតិយោបល់ (Comments) ឡើយ។

២. យុគសម័យ Web 2.0 (The Read-Write & Interactive Web: 2004 – បច្ចុប្បន្ន)៖ ការលេចឡើងនៃបច្ចេកវិទ្យា AJAX (Asynchronous JavaScript and XML), ភាសា CSS កម្រិតខ្ពស់ និងប្រព័ន្ធគ្រប់គ្រងខ្លឹមសារ (Content Management Systems - CMS) បានផ្លាស់ប្តូរវេបទៅជាវេទិកាអន្តរកម្ម។ អ្នកប្រើប្រាស់លែងត្រឹមតែជាអ្នកអានទៀតហើយ តែបានក្លាយជាអ្នកបង្កើតខ្លឹមសារ (User-Generated Content) ដូចជា បណ្តាញសង្គម (Facebook, YouTube, X), វេទិកាពិភាក្សា និងកម្មវិធី Web Applications ដូចជា Google Docs។

៣. យុគសម័យ Web 3.0 (The Semantic, AI & Decentralized Web)៖ Web 3.0 គឺជាទិសដៅអនាគតដែលផ្តោតលើ Semantic Web (កុំព្យូទ័រអាចយល់អត្ថន័យនៃទិន្នន័យបាន), ការរួមបញ្ចូលបញ្ញាសិប្បនិម្មិត (AI-driven interfaces), ក្រាហ្វិក 3D លើ Browser តាមរយៈ WebGL/WebGPU, និងបច្ចេកវិទ្យាវិមជ្ឈការ (Decentralization)។

តួនាទីរបស់អង្គការ W3C (World Wide Web Consortium)៖ W3C ត្រូវបានបង្កើតឡើងនៅឆ្នាំ ១៩៩៤ ដោយលោក Tim Berners-Lee ដើម្បីកំណត់ស្តង់ដាអន្តរជាតិរួម (Web Standards) សម្រាប់ HTML, CSS, XML និង Web Accessibility។ ប្រសិនបើគ្មាន W3C ទេ នោះ Browser នីមួយៗនឹងបង្កើតកូដផ្ទាល់ខ្លួន ដែលធ្វើឱ្យគេហទំព័រមួយមិនអាចដំណើរការបាននៅលើ Browser ផ្សេងទៀតឡើយ។

១.៣ គេហទំព័រ និងកម្មវិធីគេហទំព័រ (Website and Web Application)

នៅក្នុងការអនុវត្តវិជ្ជាជីវៈ ការបែងចែករវាង Website (គេហទំព័រព័ត៌មាន) និង Web Application (កម្មវិធីគេហទំព័រ) គឺមានសារៈសំខាន់ខ្លាំងណាស់ក្នុងការកំណត់ស្ថាបត្យកម្ម និងថវិកាគម្រោង៖

  • Website (គេហទំព័រ): ផ្តោតលើការបង្ហាញព័ត៌មាន និងខ្លឹមសារ (Content-driven)។ អ្នកប្រើប្រាស់ចូលមកដើម្បីអាន មើល ឬទាញយកទិន្នន័យ។ កម្រិតអន្តរកម្មមានកម្រិតទាប ដូចជា ការចុច Link, ការបំពេញ Form ទំនាក់ទំនងសាមញ្ញ។ ឧទាហរណ៍៖ គេហទំព័រព័ត៌មានទាន់ហេតុការណ៍, គេហទំព័របង្ហាញស្នាដៃ (Portfolio), គេហទំព័រក្រុមហ៊ុន។
  • Web Application (កម្មវិធីគេហទំព័រ): ផ្តោតលើការអនុវត្តមុខងារ និងកិច្ចការស្មុគស្មាញ (Task-driven / Software-like)។ អ្នកប្រើប្រាស់អាចបង្កើត កែប្រែ រៀបចំ និងរក្សាទុកទិន្នន័យផ្ទាល់ខ្លួន។ ទាមទារការគ្រប់គ្រងស្ថានភាពទិន្នន័យ (State Management), ការផ្ទៀងផ្ទាត់សិទ្ធិ (Authentication) និងការតភ្ជាប់ API ស្មុគស្មាញ។ ឧទាហរណ៍៖ Google Docs, Figma Web, Trello, Netflix Web Player, Canva។
លក្ខណៈប្រៀបធៀប Website (គេហទំព័រ) Web Application (កម្មវិធីវេប)
គោលបំណងស្នូល ផ្តល់ព័ត៌មាន និងចំណេះដឹង (Informational) អនុវត្តកិច្ចការ និងដោះស្រាយបញ្ហា (Perform Tasks)
កម្រិតអន្តរកម្ម (Interactivity) ទាបទៅមធ្យម (អាន, ចុចតំណភ្ជាប់, បំពេញ Form) ខ្ពស់បំផុត (បង្កើតទិន្នន័យ, drag-and-drop, real-time collaboration)
ការផ្ទៀងផ្ទាត់អ្នកប្រើ (Auth) ភាគច្រើនមិនទាមទារ Login ទេ ទាមទារការចុះឈ្មោះ និងគ្រប់គ្រងសិទ្ធិអ្នកប្រើជាចាំបាច់
ស្ថាបត្យកម្ម (Architecture) ទំព័រ HTML ឋិតិវន្ត ឬ Server-Side Rendered (SSR) Single Page Application (SPA), REST/GraphQL API, Cloud State
ឧទាហរណ៍ជាក់ស្តែង Wikipedia, BBC News, គេហទំព័រសាកលវិទ្យាល័យ Google Sheets, Spotify Web, Figma, Notion
⇄ អូសទៅស្តាំដើម្បីមើលតារាងពេញ (Scroll table horizontally)

១.៤ ការរចនាគេហទំព័រ និងការអភិវឌ្ឍគេហទំព័រ (Web Design and Web Development)

នៅក្នុងឧស្សាហកម្មបច្ចេកវិទ្យា តួនាទីទាំងពីរនេះមានការបំពេញបន្ថែមឱ្យគ្នាទៅវិញទៅមក ប៉ុន្តែទាមទារជំនាញស្នូល និងឧបករណ៍ខុសគ្នា៖

  • Web Designer (អ្នករចនាគេហទំព័រ): ផ្តោតលើរូបរាង សោភ័ណភាព និងអារម្មណ៍របស់អ្នកប្រើប្រាស់ (Look and Feel)។ ទំនួលខុសត្រូវរួមមាន ការសិក្សាអាកប្បកិរិយាអ្នកប្រើប្រាស់ (UX Research), ការគូរប្លង់រចនាសម្ព័ន្ធ (Wireframing), ការបង្កើតគំរូសាកល្បងអន្តរកម្ម (Prototyping), ការកំណត់ពណ៌ និងប្រព័ន្ធពុម្ពអក្សរ (Design Systems)។ ឧបករណ៍ប្រើប្រាស់៖ Figma, Adobe XD, Sketch, Photoshop។
  • Web Developer (អ្នកអភិវឌ្ឍគេហទំព័រ): ផ្តោតលើការយកប្លង់រចនាមកបំប្លែងទៅជាកូដកម្មវិធីដែលអាចដំណើរការបានពិតប្រាកដ (Functionality and Logic)។ ទំនួលខុសត្រូវរួមមាន ការសរសេរកូដ Frontend និង Backend, ការបង្កើតក្បួនដោះស្រាយ (Algorithms), ការតភ្ជាប់មូលដ្ឋានទិន្នន័យ (Databases), និងការធានាសុវត្ថិភាពទិន្នន័យ។ ឧបករណ៍ប្រើប្រាស់៖ VS Code, Git, Node.js, Webpack, Docker។

ចំណុចប្រសព្វ (The Intersection - UI Developer / Frontend Designer)៖ គឺជាអ្នកជំនាញដែលមានការយល់ដឹងទាំងផ្នែកសិល្បៈនៃការរចនា UI/UX និងចេះសរសេរកូដ HTML5, CSS3 និង Modern JavaScript យ៉ាងស្ទាត់ជំនាញ ដើម្បីបំប្លែងប្លង់ Design System ទៅជាកូដ Component ដែលស្អាត និងមានប្រសិទ្ធភាពខ្ពស់។

១.៥ ស្ថាបត្យកម្ម Frontend និង Backend (Frontend and Backend)

ស្ថាបត្យកម្មគេហទំព័រទំនើបដំណើរការលើគំរូ Client-Server Model ដែលបែងចែកជាពីរផ្នែកធំៗ៖

  • ១. ផ្នែកខាងមុខ (Frontend / Client-Side): គឺជាផ្នែកទាំងអស់ដែលដំណើរការដោយផ្ទាល់នៅលើ Browser របស់កុំព្យូទ័រ ឬទូរស័ព្ទរបស់អ្នកប្រើប្រាស់។ វាទទួលខុសត្រូវលើចំណុចប្រទាក់ក្រាហ្វិក (UI), គំនូរជីវចល (Animations) និងការឆ្លើយតបព្រឹត្តិការណ៍ភ្លាមៗ។ បច្ចេកវិទ្យាស្នូលរួមមាន HTML5, CSS3, JavaScript (ព្រមទាំង Frameworks ដូចជា React, Vue, Angular)។
  • ២. ផ្នែកខាងក្រោយ (Backend / Server-Side): គឺជាផ្នែកដំណើរការនៅខាងក្រោយលើម៉ាស៊ីនមេ (Remote Web Server) ដែលអ្នកប្រើប្រាស់មើលមិនឃើញ។ វាទទួលខុសត្រូវលើតក្កវិជ្ជាអាជីវកម្ម (Business Logic), ការផ្ទៀងផ្ទាត់គណនី, ការរក្សាទុក និងដំណើរការទិន្នន័យក្នុង Database, និងការបញ្ជូនទិន្នន័យតាមរយៈ REST APIs ឬ GraphQL។ បច្ចេកវិទ្យាស្នូលរួមមាន Node.js, Python, PHP, Java, Go និង Databases ដូចជា MySQL, PostgreSQL, MongoDB។

១.៦ តួនាទីរបស់ HTML, CSS និង JavaScript (Role of HTML, CSS and JavaScript)

បច្ចេកវិទ្យាទាំងបីនេះគឺជាសសរស្តម្ភដែលមិនអាចខ្វះបាន (The Holy Trinity of Web Development)។ ដើម្បីងាយស្រួលយល់ យើងអាចប្រៀបធៀបវាទៅនឹងរាងកាយរបស់មនុស្ស៖

  • HTML (HyperText Markup Language): ប្រៀបបានទៅនឹង «គ្រោងឆ្អឹង (Skeleton)»។ វាផ្តល់រចនាសម្ព័ន្ធ និងអត្ថន័យដល់ខ្លឹមសារ (Semantic Structure) ដូចជា ការកំណត់ថាទីណាជាចំណងជើង (<header>), កថាខណ្ឌ (<p>), រូបភាព (<img>), តារាង (<table>) ឬបញ្ជី (<ul>)។
  • CSS (Cascading Style Sheets): ប្រៀបបានទៅនឹង «ស្បែក និងសម្លៀកបំពាក់ (Skin & Clothing)»។ វាគ្រប់គ្រងការបង្ហាញរូបរាង សោភ័ណភាព ពណ៌ ពុម្ពអក្សរ គម្លាត ប្លង់សម្របតាមអេក្រង់ (Responsive Layouts តាម Flexbox/Grid) និងចលនាផ្លាស់ប្តូរ (Transitions/Animations)។
  • JavaScript (JS): ប្រៀបបានទៅនឹង «ប្រព័ន្ធប្រសាទ និងសាច់ដុំ (Muscles & Nervous System)»។ វាបន្ថែមឥរិយាបថ និងអន្តរកម្ម (Interactivity & Behavior) ដូចជា ការចុចប៊ូតុងបើកផ្ទាំង Modal, ការទាញទិន្នន័យពី Server ដោយមិនចាំបាច់ Reload ទំព័រ (Fetch API), និងការផ្ទៀងផ្ទាត់ទម្រង់បែបបទ (Form Validation)។

កូដគំរូនៃការធ្វើការរួមគ្នារវាង HTML, CSS និង JavaScript (VS Code Light Style គ្មាន background color)៖

<!-- ១. គ្រោងឆ្អឹង HTML5 -->
<div class="profile-card">
  <h2 id="student-name">សុខ សុវណ្ណ</h2>
  <button id="btn-greet">ចុចស្វាគមន៍</button>
</div>

/* ២. សោភ័ណភាព CSS3 */
.profile-card {
  padding: 20px;
  border-radius: 12px;
  background-color: #ffffff;
  box-shadow: 0 4px 6px rgba(0,0,0,0.1);
}

// ៣. អន្តរកម្ម JavaScript (ES6+)
const btn = document.querySelector("#btn-greet");
btn.addEventListener("click", () => {
  alert("សួស្តីនិស្សិតឆ្នាំទី ៣!");
});

១.៧ ម៉ាស៊ីនរុករក និងម៉ាស៊ីនបម្រើគេហទំព័រ (Web Browser and Web Server)

១. ម៉ាស៊ីនរុករកគេហទំព័រ (Web Browser)៖ គឺជាកម្មវិធី Software ដែលដំណើរការលើកុំព្យូទ័ររបស់អ្នកប្រើប្រាស់ (Client) ដើម្បីស្នើសុំ បកប្រែ និងបង្ហាញទំព័រគេហទំព័រ។ ផ្នែកស្នូលរបស់ Browser រួមមាន៖

  • Rendering Engine: ទទួលខុសត្រូវលើការអាន និងបកប្រែកូដ HTML និង CSS ទៅជារូបភាព និងប្លង់ភីកសែលលើអេក្រង់។ ឧទាហរណ៍៖ Blink (Google Chrome, Microsoft Edge, Opera), Gecko (Mozilla Firefox), WebKit (Apple Safari)។
  • JavaScript Engine: ទទួលខុសត្រូវលើការបកប្រែ និងដំណើរការកូដ JavaScript (JIT Compilation)។ ឧទាហរណ៍៖ V8 Engine (Google Chrome, Node.js), SpiderMonkey (Firefox), JavaScriptCore / Nitro (Safari)។

២. ម៉ាស៊ីនបម្រើគេហទំព័រ (Web Server)៖ គឺជាកុំព្យូទ័រដែលមានសមត្ថភាពខ្ពស់ ឬកម្មវិធី Software ដែលដំណើរការ ២៤/៧ ដើម្បីរង់ចាំស្តាប់ (Listening on Port 80 សម្រាប់ HTTP ឬ Port 443 សម្រាប់ HTTPS) និងឆ្លើយតបសំណូមពរពី Browser។ Web Servers ពេញនិយមរួមមាន៖ Nginx (ល្បឿនលឿនក្នុងការផ្តល់ Static files និង Reverse Proxy), Apache HTTP Server (បត់បែន និងមានប្រព័ន្ធ .htaccess), Caddy, និង Node.js HTTP Server។

១.៨ យន្តការដំណើរការនៃគេហទំព័រ (How a Website Works)

នៅពេលដែលអ្នកប្រើប្រាស់វាយបញ្ចូល URL ឧទាហរណ៍ https://www.example.com រួចចុចគ្រាប់ចុច Enter ដំណើរការលំអិតចំនួន ៦ ដំណាក់កាលនឹងកើតឡើងភ្លាមៗក្នុងរយៈពេលតែប៉ុន្មានរយមីលីវិនាទី (Milliseconds)៖

  • ដំណាក់កាលទី ១ — URL Parsing: Browser វិភាគ URL ដើម្បីញែកចេញជា Protocol (HTTPS), Domain Name (www.example.com) និង Port (443)។
  • ដំណាក់កាលទី ២ — DNS Resolution: កុំព្យូទ័រមិនស្គាល់អក្សរឈ្មោះគេហទំព័រទេ វាត្រូវការលេខ IP Address (ដូចជា 93.184.216.34)។ Browser នឹងឆែកមើលក្នុង Browser Cache, OS Cache, Router Cache ប្រសិនបើគ្មាន វានឹងសួរទៅកាន់ DNS Resolver (ISP ឬ 8.8.8.8) -> Root Server -> TLD Server (.com) -> Authoritative DNS Server ដើម្បីទទួលបានលេខ IP ពិតប្រាកដ។
  • ដំណាក់កាលទី ៣ — TCP & TLS Handshake: Browser បង្កើតការតភ្ជាប់សុវត្ថិភាពជាមួយ Server តាមរយៈ TCP 3-Way Handshake (SYN -> SYN-ACK -> ACK) រួចបន្តធ្វើ TLS/SSL Handshake ដើម្បីចរចាសោអ៊ិនគ្រីបទិន្នន័យ (Encryption Keys)។
  • ដំណាក់កាលទី ៤ — HTTP Request Transmission: Browser ផ្ញើសំណើ HTTP GET Request ទៅកាន់ Web Server អមជាមួយ Headers ដូចជា User-Agent, Accept-Encoding, Cookies។
  • ដំណាក់កាលទី ៥ — Server Processing & HTTP Response: Web Server ដំណើរការសំណើ រកមើលឯកសារ HTML ឬទាញទិន្នន័យពី Database រួចផ្ញើ HTTP Response Status Code 200 OK ត្រឡប់មកវិញ អមជាមួយ Payload កូដ HTML។
  • ដំណាក់កាលទី ៦ — Critical Rendering Path (CRP): Browser ដំណើរការគន្លងនៃការបង្ហាញទំព័រ៖
    • កសាង DOM Tree (Document Object Model) ពីកូដ HTML
    • កសាង CSSOM Tree (CSS Object Model) ពីកូដ CSS
    • រួមបញ្ចូលគ្នាបង្កើត Render Tree
    • គណនាប្លង់ និងទីតាំងភីកសែល (Layout / Reflow)
    • គូរពណ៌ និងរូបភាពលើអេក្រង់ (Paint & Compositing)

១.៩ ប្រភេទគេហទំព័រទាំង ៦ (Types of Websites)

នៅក្នុងទីផ្សារការងារ និងការរចនាគេហទំព័រអាជីព គេហទំព័រត្រូវបានបែងចែកជា ៦ ប្រភេទចម្បង៖

  • ១. គេហទំព័រឋិតិវន្ត (Static Website): គឺជាគេហទំព័រដែលមានឯកសារ HTML, CSS និង JavaScript ថេរនៅលើ Server។ មាតិកាមិនផ្លាស់ប្តូរទេ លុះត្រាតែអ្នកអភិវឌ្ឍន៍ចូលទៅកែកូដឯកសារផ្ទាល់។ គុណសម្បត្តិ៖ ផ្ទុកលឿនបំផុត (Sub-second loading), សុវត្ថិភាពខ្ពស់បំផុត (មិនងាយរងការវាយប្រហារតាម SQL Injection), និងតម្លៃ Hosting ថោក។ ករណីប្រើប្រាស់៖ ឯកសារបច្ចេកទេស (Documentation), Landing Pages, ប្លុកសាមញ្ញ។
  • ២. គេហទំព័រឌីណាមិក (Dynamic Website): គឺជាគេហទំព័រដែលទំព័រ HTML ត្រូវបានបង្កើតឡើងដោយស្វ័យប្រវត្តិតាមរយៈ Server Scripting (PHP, Node.js, Python) ដោយទាញទិន្នន័យចេញពី Database (MySQL, PostgreSQL)។ គុណសម្បត្តិ៖ ងាយស្រួលគ្រប់គ្រងទិន្នន័យរាប់ពាន់ទំព័រតាមរយៈ Dashboard (CMS), គាំទ្រការស្វែងរក និងប្រព័ន្ធសមាជិក។ ករណីប្រើប្រាស់៖ សារព័ត៌មានអនឡាញ, បណ្តាញសង្គម, វេទិកាពិភាក្សា។
  • ៣. គេហទំព័រពាណិជ្ជកម្មអេឡិចត្រូនិក (E-Commerce Website): គឺជាគេហទំព័រពាណិជ្ជកម្មសម្រាប់លក់ទំនិញ ឬសេវាកម្មអនឡាញ។ លក្ខណៈពិសេសស្នូល៖ កាតាឡុកទំនិញ (Product Catalog), កន្ត្រកទំនិញ (Shopping Cart), ប្រព័ន្ធទូទាត់ប្រាក់ (Payment Gateway ដូចជា Stripe, PayPal, Bakong KHQR), និងការគ្រប់គ្រងស្តុក។ ករណីប្រើប្រាស់៖ Amazon, eBay, Shopify Stores។
  • ៤. គេហទំព័របង្ហាញស្នាដៃផ្ទាល់ខ្លួន (Portfolio Website): គឺជាគេហទំព័របង្ហាញស្នាដៃ និងសមត្ថភាពរបស់បុគ្គល ឬ Freelancer (Web Designers, Developers, វិចិត្រករ)។ ផ្តោតលើការបង្ហាញ Case Studies, ជំនាញ, ប្រវត្តិការងារ និងទម្រង់ទំនាក់ទំនង (Call-to-Action) ដើម្បីទាក់ទាញអតិថិជន ឬនិយោជក។
  • ៥. គេហទំព័រស្ថាប័ន / ក្រុមហ៊ុន (Corporate Website): គឺជាគេហទំព័រតំណាងឱ្យក្រុមហ៊ុន ស្ថាប័ន ឬសាជីវកម្ម។ គោលបំណងចម្បងគឺកសាងទំនុកចិត្ត (Brand Credibility), បង្ហាញសេវាកម្ម, វប្បធម៌ស្ថាប័ន, ព័ត៌មានវិនិយោគិន និងបណ្តាញទំនាក់ទំនងផ្លូវការ។
  • ៦. គេហទំព័រអប់រំ (Educational Website): គឺជាគេហទំព័ររបស់សាលារៀន សាកលវិទ្យាល័យ ឬវេទិកាសិក្សាអនឡាញ (Coursera, Khan Academy)។ មុខងារស្នូលរួមមាន ប្រព័ន្ធគ្រប់គ្រងការសិក្សា (LMS - Moodle, Canvas), មាតិកាមេរៀន, តារាងកាលវិភាគប្រឡង និងការចុះឈ្មោះវគ្គសិក្សា។

១.១០ លំហូរការងាររចនាគេហទំព័រអាជីព (Web Design Workflow)

ការបង្កើតគេហទំព័រអាជីពមួយប្រកបដោយគុណភាពខ្ពស់ ត្រូវអនុវត្តតាមលំហូរការងារស្តង់ដាចំនួន ៨ ដំណាក់កាល៖

  • ១. ការស្រាវជ្រាវ និងប្រមូលតម្រូវការ (Discovery & Research): ជួបពិភាក្សាជាមួយអតិថិជន កំណត់គោលដៅគេហទំព័រ កំណត់ក្រុមអ្នកប្រើប្រាស់គោលដៅ (Target Audience) និងវិភាគដៃគូប្រកួតប្រជែង។
  • ២. ស្ថាបត្យកម្មព័ត៌មាន (Information Architecture): រៀបចំផែនទីគេហទំព័រ (Sitemap) និងរចនាសម្ព័ន្ធលំហូរទិន្នន័យ (User Flow) ដើម្បីធានាថាអ្នកប្រើប្រាស់អាចស្វែងរកព័ត៌មានបានលឿន។
  • ៣. ការគូរប្លង់បឋម (Wireframing): គូរប្លង់ព្រាងសាមញ្ញដោយគ្មានពណ៌ (Low-fidelity wireframes) ដើម្បីរៀបចំទីតាំងធាតុ (Header, Hero, Cards, Footer)។
  • ៤. ការរចនា UI/UX លម្អិត (UI/UX Design): បង្កើតប្លង់ច្បាស់លាស់ពេញលេញ (High-fidelity mockup) ដោយកំណត់ពណ៌ ពុម្ពអក្សរ រូបភាព និងធ្វើគំរូអន្តរកម្មសាកល្បង (Interactive Prototype) លើ Figma។
  • ៥. ការអភិវឌ្ឍ Frontend & Backend (Development): សរសេរកូដ Semantic HTML5, CSS3 និង JavaScript ព្រមទាំងតភ្ជាប់ Backend APIs និង Database។
  • ៦. ការធ្វើតេស្តគុណភាព (Quality Assurance - QA): ធ្វើតេស្តលើទំហំអេក្រង់ផ្សេងៗ (Responsive Testing), ត្រួតពិនិត្យភាពស៊ីគ្នាលើ Browser (Cross-Browser Testing), ពិនិត្យល្បឿន និងសុវត្ថិភាព។
  • ៧. ការដាក់ឱ្យដំណើរការ (Deployment): បង្ហោះគេហទំព័រទៅកាន់ Production Server (Hosting, Cloud, CDN, Domain setup)។
  • ៨. ការថែទាំជាប្រចាំ (Maintenance & Updates): តាមដានដំណើរការ (Performance Monitoring), បម្រុងទុកទិន្នន័យ (Backups), និងធ្វើបច្ចុប្បន្នភាពខ្លឹមសារជាប្រចាំ។

១.១១ ឧបករណ៍សំខាន់ៗក្នុងការងាររចនាគេហទំព័រ (Web Design Tools)

  • ឧបករណ៍រចនា UI/UX (Design & Prototyping): Figma (ឧបករណ៍លេខ ១ បច្ចុប្បន្នសម្រាប់ UI/UX និងការសហការជាក្រុម), Adobe XD, Sketch, Penpot (Open-source)។
  • កម្មវិធីសរសេរកូដ (Code Editors): Visual Studio Code (VS Code - កម្មវិធីកូដពេញនិយមបំផុតក្នុងពិភពលោក), WebStorm, Sublime Text។
  • ប្រព័ន្ធគ្រប់គ្រងកំណែកូដ (Version Control): Git (គ្រប់គ្រងប្រវត្តិកូដ) និង GitHub / GitLab (កន្លែងផ្ទុកកូដ និងធ្វើការងារជាក្រុម)។
  • ឧបករណ៍បង្កើនប្រសិទ្ធភាពរូបភាព (Asset Optimization): Squoosh (Google Image Compression), TinyPNG, SVGO (Optimize SVG vectors) ដើម្បីកាត់បន្ថយទំហំរូបភាពបង្កើនល្បឿនគេហទំព័រ។
  • ឧបករណ៍ត្រួតពិនិត្យលើ Browser (Inspection Tools): Chrome DevTools, Firefox Developer Edition, Lighthouse (សម្រាប់ Audit SEO, Accessibility, Core Web Vitals)។

១.១២ សេចក្តីផ្តើមអំពីឧបករណ៍អ្នកអភិវឌ្ឍន៍នៅលើ Browser (Introduction to Browser DevTools)

Browser Developer Tools (DevTools) គឺជាសំណុំឧបករណ៍វិជ្ជាជីវៈដែលត្រូវបានបង្កប់ស្រាប់នៅក្នុង Modern Web Browsers ដូចជា Google Chrome និង Microsoft Edge។ របៀបបើក DevTools៖ ចុចគ្រាប់ចុច F12 ឬ Ctrl + Shift + I (លើ Windows) ឬចុចកណ្ដុរខាងស្តាំលើទំព័រ រួចជ្រើសរើស «Inspect»។

ផ្ទាំងសំខាន់ៗទាំង ៦ ក្នុង DevTools ដែលនិស្សិតត្រូវក្តាប់ឱ្យបានស្ទាត់ជំនាញ៖

  • ១. ផ្ទាំង Elements: បង្ហាញរចនាសម្ព័ន្ធ DOM Tree នៃកូដ HTML ជាក់ស្តែង។ និស្សិតអាចចុចកែប្រែកូដ HTML ឬកែប្រែស្ទីល CSS (Styles Panel) ផ្ទាល់បានភ្លាមៗ (Real-time Live Editing)។
  • ២. ផ្ទាំង Console: កន្លែងបង្ហាញសារកំហុស (JavaScript Errors), ការព្រមាន (Warnings) និងជាកន្លែងដែលអ្នកអភិវឌ្ឍន៍អាចវាយបញ្ជាកូដ JavaScript ដើម្បីធ្វើតេស្តមុខងារភ្លាមៗ។
  • ៣. ផ្ទាំង Network: តាមដានរាល់ការស្នើសុំឯកសារតាមបណ្តាញ (HTTP Requests)។ វាបង្ហាញពីឈ្មោះឯកសារ, Method (GET/POST), Status Code (200, 404), ទំហំឯកសារ (Size) និងរយៈពេលដែលត្រូវចំណាយក្នុងការទាញយក (Time / Waterfall)។
  • ៤. ផ្ទាំង Sources: កន្លែងផ្ទុកកូដប្រភព (Source Code) ទាំងអស់នៃគេហទំព័រ។ ប្រើប្រាស់សម្រាប់ដាក់ចំណុចផ្អាក (Breakpoints) ដើម្បីបំបាត់កំហុស (Debugging) ក្នុងកូដ JavaScript។
  • ៥. មុខងារ Responsive Device Mode: អនុញ្ញាតឱ្យអ្នករចនាធ្វើការក្លែងទំហំអេក្រង់ទូរស័ព្ទ (ដូចជា iPhone, Samsung Galaxy) ឬ Tablet ដើម្បីពិនិត្យមើលភាពរៀបរយនៃ Responsive Layout។
  • ៦. ផ្ទាំង Lighthouse Audit: ឧបករណ៍ស្វ័យប្រវត្តរបស់ Google សម្រាប់វាយតម្លៃគុណភាពគេហទំព័រលើ ៤ ចំណុច៖ Performance (ល្បឿន), Accessibility (លទ្ធភាពប្រើប្រាស់), Best Practices (ការអនុវត្តល្អ), និង SEO (ការបង្កើនប្រសិទ្ធភាពម៉ាស៊ីនស្វែងរក)។

សេចក្តីសង្ខេបមេរៀន (Chapter Summary)

ជំពូកទី ១ នេះបានផ្តល់នូវគ្រឹះដ៏រឹងមាំសម្រាប់និស្សិតឆ្នាំទី ៣ ក្នុងការឈានជើងចូលទៅក្នុងពិភពវិជ្ជាជីវៈនៃការរចនាគេហទំព័រ។ យើងបានសិក្សាថា គេហទំព័រទំនើបកើតឡើងពីការរួមផ្សំរវាង HTML (រចនាសម្ព័ន្ធ), CSS (សោភ័ណភាព) និង JavaScript (អន្តរកម្ម) នៅលើស្ថាបត្យកម្ម Client-Server។ ការយល់ដឹងពីលំហូរនៃ HTTP Request, DNS Resolution និង Critical Rendering Path ជួយឱ្យយើងមិនត្រឹមតែអាចរចនាគេហទំព័រឱ្យមានសោភ័ណភាពស្អាតប៉ុណ្ណោះទេ ប៉ុន្តែថែមទាំងដំណើរការបានលឿន និងប្រកបដោយសុវត្ថិភាព។ ប្រភេទគេហទំព័រនីមួយៗទាមទារនូវយុទ្ធសាស្ត្ររចនា និងបច្ចេកវិទ្យាសមស្រប។ ឧបករណ៍ DevTools គឺជាអាវុធដ៏មានអានុភាពដែលជួយយើងក្នុងការវិភាគ និងដោះស្រាយបញ្ហាបច្ចេកទេសប្រចាំថ្ងៃ។

សំណួរត្រួតពិនិត្យការយល់ដឹង (Review & Discussion Questions)

  1. ចូរពន្យល់ពីគោលការណ៍គ្រឹះទាំង ៤ នៃការរចនាគេហទំព័រទំនើប (Usability, Accessibility, Aesthetics, Responsiveness)។
  2. ចូរប្រៀបធៀបភាពខុសគ្នារវាង Website និង Web Application។ លើកឧទាហរណ៍ជាក់ស្តែងយ៉ាងតិចចំនួន ២ សម្រាប់ប្រភេទនីមួយៗ។
  3. ហេតុអ្វីបានជាគេប្រៀបធៀប HTML, CSS និង JavaScript ទៅនឹង គ្រោងឆ្អឹង ស្បែក និងសាច់ដុំរបស់មនុស្ស? ចូរពន្យល់ដោយលើកឧទាហរណ៍កូដខ្លីមួយ។
  4. ចូររៀបរាប់ពីដំណើរការ ៦ ដំណាក់កាលនៅពេលដែលអ្នកប្រើប្រាស់វាយ URL ចូលទៅក្នុង Browser រហូតដល់ទំព័របង្ហាញចប់។
  5. តើគេហទំព័រឋិតិវន្ត (Static) និងគេហទំព័រឌីណាមិក (Dynamic) មានគុណសម្បត្តិ និងគុណវិបត្តិខុសគ្នាយ៉ាងដូចម្តេចខ្លះ? តើពេលណាដែលយើងគួរជ្រើសរើស Static Website?
